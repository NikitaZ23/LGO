# LGO - Local Generation Object

LGO - локальный Windows-сервис для генерации 3D-объектов из одного изображения, четырёх или шести ракурсов на базе Hunyuan3D-2.1.

Приложение запускается локально, использует модели и исходники Hunyuan3D на вашем компьютере и даёт удобный web-интерфейс для работы с генерациями.

## Возможности

- режимы входа: одно изображение, четыре ракурса `front`, `back`, `left`, `right` или шесть с дополнительными `top`, `bottom` для текстуры;
- пресеты качества геометрии: Fast, Balanced, High;
- пресеты типа объекта: Character, Rock / stone, Building, Hard surface, Cloth, Creature;
- пресеты экспортного масштаба: Small prop, Character, Vehicle, Building, Monument и Custom height;
- генерация без текстуры или с PBR-текстурой;
- отдельный выбор скорости текстуры: Fast, Balanced, High;
- повторный запуск текстурирования для уже созданной белой модели;
- постобработка: очистка фона, удаление нижней плоской подставки, сглаживание, weighted normals, базовая правка пальцев рук и ног;
- экспорт в GLB, OBJ и FBX;
- конвертация выбранного готового результата кнопками `Export OBJ` и `Export FBX` без повторной генерации; работает и для версий текстуры из истории;
- история генераций с возможностью загрузить результат обратно в окно просмотра;
- отдельный рейтинг 1-5 звёзд для белой модели и для текстурированного результата.

## Четыре и шесть ракурсов

В режиме `4 views` все четыре изображения `front`, `back`, `left`, `right` используются и для геометрии, и как референсы текстурной модели Paint. Это относится также к `Add texture` и `Re-run texture` для сохранённых заданий с четырьмя входными картинками. Старые текстуры автоматически не меняются: загрузите модель из истории и нажмите `Re-run texture`, чтобы использовать все ракурсы. `Re-bake color` не перегенерирует текстуру по картинкам.

В режиме `6 views` загрузите один и тот же объект спереди, сзади, слева, справа, сверху и снизу. Последние два поля подписаны как референсы текстуры.

Геометрию Hunyuan строит по четырём боковым ракурсам: установленная shape-модель не поддерживает камеры сверху и снизу. Все шесть изображений передаются в reference attention текстурной модели Paint. Это общие референсы внешнего вида, а не точное проецирование фотографий на соответствующие стороны; совпадение отдельных деталей и скрытых полостей не гарантируется.

Входные изображения сохраняются в `runs/<job>/input/`, очищенные копии в `input/cleaned/`. `Add texture` и `Re-run texture` используют все шесть сохранённых ракурсов. При `No texture` верх и низ сохраняются для последующего текстурирования и не влияют на белую модель. `Re-bake color` изменяет уже полученный цвет без повторного запуска Paint.

В этом режиме текстурирование использует минимум шесть выходных ракурсов, включая верх и низ, даже при `Fast`; разрешение и remesh остаются из выбранного `Texture speed`. Потребление видеопамяти и время могут увеличиться. Для проверки входов в `manifest.json` записываются `shape_input_views` и `texture_reference_views`; лог текстурирования перечисляет использованные референсы.

## Что не входит в репозиторий

В репозиторий намеренно не добавлены тяжёлые локальные данные:

- `.venv/` - виртуальное окружение Python;
- `.cache/` - кеши Hugging Face и Python;
- `vendor/` - исходники Hunyuan3D-2.1;
- `wheelhouse/` - локальные CUDA/PyTorch wheels;
- `runs/` - история генераций, входные картинки, логи и готовые модели;
- `logs/` - логи сервиса;
- веса моделей Hunyuan3D.

Эти файлы должны храниться локально и не должны попадать в GitHub.

## Требования

- Windows 10/11;
- Python 3.10;
- NVIDIA GPU с поддержкой CUDA;
- CUDA Toolkit, если нужно собирать native rasterizer для текстур;
- Blender;
- скачанные веса Hunyuan3D-2.1 с Hugging Face.

Основные пути настраиваются в:

```text
config/lgo_config.json
```

В конфиге можно использовать `{project_root}` для путей, которые должны зависеть от папки проекта.

## Установка

Склонировать проект:

```powershell
git clone https://github.com/NikitaZ23/LGO.git
cd LGO
```

Создать виртуальное окружение:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\setup_venv.ps1
```

Если Python 3.10 не находится автоматически, передайте путь явно:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\setup_venv.ps1 -Python C:\Path\To\Python310\python.exe
```

Скачать исходники Hunyuan3D-2.1 в папку `vendor`:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\install_hunyuan_source.ps1
```

Установить AI runtime:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\install_ai_runtime.ps1
```

## Запуск

Запуск в обычном окне:

```powershell
.\start-lgo.bat
```

Запуск в фоне:

```powershell
.\start-lgo-background.bat
```

Если `.venv` ещё не создан после `git clone`, стартовые батники предложат создать его через `scripts\setup_venv.ps1`.
Если на этой машине существует рабочая копия `E:\AI\Projects\LGO`, стартовые батники используют её как основной проект, чтобы сохранялась старая история `runs`. Другой путь можно задать через переменную окружения `LGO_HOME`.

Остановка:

```powershell
.\stop-lgo.bat
```

После запуска открыть:

```text
http://127.0.0.1:7865
```

В верхней панели фронта есть кнопки:

- `Refresh` - обновить статус окружения;
- `Restart` - перезапустить локальный сервис LGO;
- `Shutdown` - выключить локальный сервис LGO.

Если сервис был запущен через `start-lgo.bat`, при штатном `Restart` или `Shutdown` старое окно `cmd` закроется само.
Окно останется с паузой только если сервер завершился с ошибкой, чтобы можно было прочитать сообщение.

После `Shutdown` включить сервис обратно можно через `start-lgo-background.bat` или `start-lgo.bat`.
Лог автоперезапуска пишется в `logs/service-restart.log`.

## Работа с результатами

Каждая генерация сохраняется в папке:

```text
runs/<job-id>/
```

Внутри job обычно есть:

- `input/` - исходные изображения;
- `input/cleaned/` - очищенные изображения после preprocessing;
- `output/white_mesh.glb` - белая модель без текстуры;
- `output/textured_mesh.glb` - текстурированная версия на геометрии `white_mesh.glb`;
- `output/textured_mesh.original.glb` - скрытая резервная версия на remesh-геометрии paint-пайплайна;
- `job.json` - состояние задачи, настройки, outputs, предупреждения и рейтинги;
- `run.log` - лог выполнения.

История на фронте строится из папок `runs`.
При загрузке из истории фронт сначала открывает `white_mesh.glb`, если он есть.
Текстурированный `textured_mesh.glb` остается доступен через переключатель `Textured mesh` в окне результата.
Чекбокс `Показать с текстурой` в заголовке результата переключает viewer между белой и текстурированной GLB-версией.
Фронт не накладывает эти модели друг на друга.
После paint-прохода LGO переносит цвет с remesh-результата обратно на исходную белую геометрию через vertex colors.
Если перенос не удался, пайплайн использует резервный remesh-вариант и пишет предупреждение в `job.json`.
Кнопка `Re-run texture` заново запускает тяжелый Hunyuan paint-pass.
Кнопка `Re-bake color` использует уже сохраненные `textured_mesh.obj` и `textured_mesh.jpg`, быстро пересчитывает цвет на `white_mesh.glb` и применяет текущий цветовой профиль выбранного типа объекта.
Слайдер `Albedo` управляет финальной силой цвета только для `Re-bake color`: `1.00x` оставляет профиль без ручной поправки, значения выше делают результат ярче, ниже - темнее.
`Re-bake color` активен только когда у job есть `white_mesh.glb`, `textured_mesh.obj` и `textured_mesh.jpg`.

## Экспорт готового результата

Выберите модель или версию текстуры в истории, затем нужный вариант в просмотре (`White mesh` / `Textured mesh`). Кнопки `Export OBJ` и `Export FBX` конвертируют именно отображаемый GLB, без повторной генерации и изменения исходного файла. После завершения рядом появится ссылка скачивания; повторный экспорт неизменённого результата использует готовый файл.

OBJ скачивается ZIP-архивом с OBJ, MTL и изображениями: при импорте сохраняйте структуру архива. FBX содержит встроенные изображения. Старые результаты с цветами вершин сохраняют vertex colors; для OBJ нужна программа с поддержкой этого расширения. Отображение PBR-материалов может отличаться между программами и форматами.

Экспорт требует настроенного Blender. Пока с выбранной моделью идёт генерация, текстурирование или конвертация, кнопки недоступны. Отключение сервиса останавливает и процесс экспорта.

## Примечания

Текстурирование обычно заметно медленнее генерации геометрии. Практичный порядок работы:

1. Сначала сгенерировать белую модель без текстуры.
2. Оценить форму в viewer.
3. Если форма хорошая, нажать `Add texture`.
4. Начинать с Fast texture, а Balanced или High использовать только для удачных моделей.

Тип объекта влияет на постобработку. Для персонажей используйте `Character`, для ткани - `Cloth`.
Для зданий, архитектуры, стен и крыш используйте `Building`: этот режим меньше сглаживает геометрию, не применяет finger/toe guard и держит PBR-текстуру более матовой и нейтральной.
Для механики, оружия, брони и четких промышленных форм используйте `Hard surface`.
Для камней, минералов и неровных природных объектов используйте `Rock / stone`: этот режим делает текстуру матовее, приглушает лишний PBR-блеск и мягче сглаживает видимые грани.

Чекбокс **«Учитывать высоту и длину»** включает изменение размеров. Без галочки `Height` и `Length` не применяются: сохраняется масштаб, полученный от генератора, без нормализации до высоты человека. В новом браузере галочка выключена; выбор сохраняется локально. При загрузке истории восстанавливается режим выбранного задания; старые задания без этого флага считаются созданными с включённым масштабированием. В API флаг передаётся как `apply_dimensions=true/false`; при `false` сервер игнорирует оба размера, даже если они переданы. Отсутствие флага сохраняет прежнее поведение API.

При включённой галочке `Scale` задает физический размер экспортируемой модели по высоте. Например, `Character` нормализует результат примерно до 1.8 м, `Building` - до 24 м, а `Custom` позволяет указать высоту вручную. Масштаб применяется перед сохранением `white_mesh.glb`, поэтому текстурированная версия и дополнительные экспорты наследуют тот же размер. Это не добавляет детализацию само по себе, а только меняет реальные единицы/габариты объекта.

`Length` задаёт длину спереди назад в метрах (обычно ось Z) независимо от `Height`, для любого пресета масштаба. Пустое поле `Auto` сохраняет исходные пропорции при масштабировании по высоте. Если длина указана, после расчёта высоты отдельно масштабируется продольная ось: высота остаётся заданной, ширина наследует масштаб высоты, а пропорции длины изменяются. Допустимый диапазон: 0.01–10000 м. При настроенной вертикали Z продольной осью становится X.

Длина сохраняется в параметрах задания, истории и версиях текстур. Она применяется при `Create Job`; загрузка истории, `Re-run texture` и `Re-bake color` сами по себе не меняют размеры существующей геометрии.

Если на модели сильно видны полигоны, новые GLB проходят через Blender post-process со сглаживанием и weighted normals. Это улучшает отображение в viewer, но не заменяет полноценную высокополигональную реконструкцию.

### Детали и материалы техники и зданий

Для `Hard surface` и `Building` включён `generation.texture_preserve_geometry`: Paint получает исходную белую сетку без упрощения, а результат сохраняется с UV-развёрткой, цветовой картой и картами metallic/roughness. Перед экспортом проверяется совпадение треугольников и координат; UV-швы могут дублировать вершины, но форма не меняется. Если новая UV-сетка не совпала, сервис оставляет белую модель, а не подменяет её другой геометрией.

В этих пресетах отключены геометрическое сглаживание, размытие текстуры, автоматическое осветление и обесцвечивание. Сглаживание нормалей остаётся; конвертер Blender больше не меняет материалы принудительно. `Albedo = 1` и `Color = 1` сохраняют полученные от Paint цвета. `Re-bake color` применяет выбранные значения к исходной карте, без накопления изменений между повторными запусками. Это не гарантирует точного совпадения с референсами: детали, которые генератор не восстановил, такая обработка не создаёт.

Для старого объекта нажмите `Re-run texture`, чтобы получить новый UV-результат. Старые упрощённые текстуры при `Re-bake color` используют совместимый перенос цвета на вершины с корректным линейным цветовым пространством. Утраченные ранее детали этим не восстанавливаются. Чтобы пересоздать геометрию без прежнего сглаживания, нужен `Create Job`. История не переписывается автоматически.

Сохранение исходной сетки может увеличить время UV-развёртки и расход памяти. Переключатель `texture_preserve_geometry: false` в соответствующем пресете возвращает прежний упрощённый путь. Модуль `tests/test_texture_fidelity.py` проверяет цвет, UV, PBR, геометрию и повторный re-bake без генерации нейросетью. Для дополнительного теста реального Blender установите `LGO_TEST_BLENDER=1` при запуске `python -m unittest discover -s tests` в окружении генератора.

Большие модели, веса, локальные генерации и временные файлы не коммитьте в GitHub.
